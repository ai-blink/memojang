```text
C:\ai\projects\memojang 에서 이어서 작업해줘.

먼저 `CLAUDE.md`, `doc/INTENT.md`, `rules/dev-context.md`, `rules/dev-progress.md`, `rules/dev-roadmap.md`, `rules/dev-arch.md`, `rules/dev-ux.md`, `docs/ARCHITECTURE.md`를 읽고 현재 의도와 범위를 확인해.

목표:
Memojang의 V1 방향을 “단순 Markdown 표 편집”보다 넓게 보고, 실제 에디터다운 문서 경험을 설계/구현할 방향을 잡아줘.

중점:
- Markdown preview 개선
- source 편집과 preview의 실시간 동기화
- `.txt` / `.md` 맞춤 지원
- Memojang 고유 문서 확장자 검토
- 이미지 첨부/삽입 UX
- Markdown 문서와 이미지 asset 관리 방식
- Notepad-like 가벼운 UX 유지

검토 질문:
1. `.txt`
   - 순수 텍스트로 유지할 기능
   - Markdown 기능을 숨기거나 최소화할 기준
   - 인코딩/줄끝/상태바 표시 정책

2. `.md`
   - source editing + preview split 구조
   - 실시간 preview debounce
   - preview scroll sync
   - 이미지 drag/drop 또는 paste 처리
   - Markdown image syntax 삽입 방식
   - local image path vs assets folder 정책

3. 고유 확장자
   - 예: `.memojang`, `.mjd`, `.mmdoc` 같은 자체 문서 포맷 검토
   - 내부 구조 후보:
     - plain Markdown + sidecar assets folder
     - zip package
     - JSON metadata + Markdown body
   - 장단점:
     - 백업/호환성
     - Git diff 가능성
     - 이미지 첨부 안정성
     - 향후 설정/metadata 확장성
   - V1에서 고유 확장자를 도입해야 하는지, 아니면 V2로 미룰지 판단

4. 이미지 첨부
   - paste image from clipboard
   - drag/drop image file
   - relative assets folder 생성
   - 파일 저장 전 임시 이미지 처리
   - 이미지 삭제/이름 충돌/경로 이동 정책
   - Markdown preview에 안전하게 표시하는 방식

5. 실시간 편집
   - 현재 WPF TextBox 기반에서 가능한 수준
   - preview update debounce 필요 여부
   - 큰 문서에서 성능 저하 방지
   - Markdown parser/renderer 개선 방향
   - WebView2 도입 여부 검토
   - WPF FlowDocument 유지 여부 검토

해야 할 일:
- 현재 코드 구조를 확인하고 `MarkdownPreviewParser`, `MarkdownPreviewDocumentFactory`, `MainWindow`, file command 구조를 분석해.
- 구현 전에 `notes/plans/2026-07-07-document-format-preview-plan.md`에 짧은 계획을 작성해.
- 계획에는 다음 섹션을 포함해:
  - Finish Line
  - Scope Limit
  - Acceptance Checks
  - Recommended Direction
  - Minimal Implementation Slice
  - Follow-ups

추천 방향:
- V1은 `.txt`와 `.md`를 확실히 지원.
- 고유 확장자는 바로 구현하지 말고, 먼저 문서로 설계만 남겨.
- 이미지 첨부는 `.md` 기준으로 `filename.assets/` 또는 `assets/` 폴더에 복사하고 상대 Markdown 링크를 삽입하는 방식부터 검토.
- preview는 현재 FlowDocument 기반을 유지하되, 이미지 표시와 debounce부터 개선.
- WebView2나 full WYSIWYG는 V1 기본 구현으로 바로 키우지 말고 장단점 검토만 해.

가능하면 최소 구현:
- `.txt` / `.md` 파일 타입 감지
- 상태바에 문서 모드 표시
- Markdown preview update debounce
- Markdown image syntax preview 지원
- 이미지 파일 drag/drop 시 Markdown image link 삽입
- 저장된 `.md` 기준 상대 assets 경로 정책
- 관련 unit test 추가

검증:
- `dotnet build .\Memojang.sln`
- `dotnet test .\Memojang.sln`
- 앱 실행 smoke
- `git diff --check`

완료 후:
- 변경 파일 요약
- 실행한 검증 명령과 결과
- `.txt`, `.md`, 고유 확장자에 대한 추천 결론
- 다음 구현 슬라이스 제안
- 커밋은 별도 지시 전에는 하지 말고 대기

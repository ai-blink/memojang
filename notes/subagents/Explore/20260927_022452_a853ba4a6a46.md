## 2. Windows 메모장(Win11) 대비 기본기 격차

- **인코딩 선택 저장(ANSI/UTF-8/UTF-8 BOM/UTF-16 LE)**: 메모장은 저장 시 인코딩을 고를 수 있음. Memojang은 항상 UTF-8 BOM 없이 고정 저장, 읽기도 인코딩 자동 판별이 없음(`MainWindow.Files.cs:21,52,136`).
- **줄바꿈 유지**: 메모장은 열 때 감지한 원본 줄바꿈을 저장 시 유지. Memojang은 감지(`Shell/LineEnding.cs`)만 하고 저장 시 실제로 원본 줄바꿈으로 정규화하는 로직이 코드에 안 보임 — 확인 필요(WPF TextBox 내부 동작에 의존할 수 있음).
- **Ctrl+H(바꾸기 열기)**: 없음.
- **자동저장/충돌 복구**: 없음.
- **세션 복원(마지막 열려있던 탭)**: 명시적으로 범위 제외(`notes/plans/2026-07-10-settings-persistence-fix-plan.md:18`).
- **Ctrl+마우스휠 줌**: 없음.
- **인쇄**: 없음.
- **다크모드 실시간 시스템 추종**: 시작 시 1회만 반영, 실행 중 OS 테마 변경 무반응(`Theme/AppThemeService.cs:46-49`).
- **word wrap 실제 토글**: 메뉴에 있지만 비활성·항상 체크·실제로는 꺼져 있음(`MainWindow.xaml:250`, `:485`) — 메모장 기본은 줄바꿈 켜짐인데 Memojang 기본은 꺼짐이면서 UI는 켜짐이라고 보여줌.
- **다중 실행/파일 잠금 경고**: 다른 창에서 같은 파일 열림 여부 확인 없음(확인 필요, 코드 검토로는 안 보임).

## 4. 구조 관찰

- **500줄 룰**: `MainWindow.xaml`이 정확히 500줄(CLAUDE.md "under 500 lines"에 근접/경계). 나머지 `.cs` 파일은 모두 500줄 미만(최대 `MainWindow.xaml.cs` 443줄).
- **아키텍처 문서와 실구현 불일치**: `rules/dev-arch.md:8-9`는 `src/Memojang.App/Markdown/`, `Markdown/Tables/` 레이어와 "Markdig pipeline" 사용을 계획했지만, 실제로는 전부 `Shell/` 네임스페이스에 자체 정규식/라인 기반 파서로 구현되어 있고 Markdig 패키지 참조도 없음(`Memojang.App.csproj`). 문서가 실제 구조를 반영하지 못함.
- **partial class 책임 분리는 대체로 단일 책임**을 지키고 있음(`MainWindow.Files.cs`, `.Tabs.cs`, `.Search.cs` 등 파일명=책임 일치). 다만 `MainWindow.Settings.cs`(29줄)는 매우 얇고, `AppSettingsStore`가 실제로 저장하는 필드(최근파일·캡처요청)와 UX 문서가 요구하는 범위(테마/글꼴/줌/줄바꿈) 사이 간극이 이 파일 하나로 안 보이게 가려져 있음.
- **테스트 커버 공백**: `tests/Memojang.Tests/`는 `Shell/*` 순수 로직(설정 저장, 문서모드, 이미지, 줄검색, 시작경로)만 테스트하고, `MainWindow` 관련 통합 동작(탭 전환, 저장 흐름, 캡처 제외 요청/상태 분리, 메뉴 로컬라이즈)은 테스트가 전혀 없음(`Grep "MainWindow"` 결과 0건). `rules/dev-arch.md:22` "Smoke test app startup ... once UI automation exists"라고 스스로 인정한 상태.
- **`samples/` 폴더 없음**: `CLAUDE.md` 폴더맵이 언급하는 `samples/`(Markdown 픽스처)가 실제로 생성되지 않음.
- **워킹트리 미커밋 변경**은 요청/실제 상태 분리(캡처 제외)와 설정 영속화 배선(`MainWindow.Settings.cs`, `Shell/AppSettingsStore.cs`, 관련 테스트)이 한 슬라이스로 진행 중이며, 계획 문서(`notes/plans/2026-07-10-settings-persistence-fix-plan.md`)의 Scope Limit(탭/선택/창위치 제외)과 일치함 — 범위 이탈 없음.

## 5. 상위 10개 개선 우선순위

제품 목표(경량 Notepad-like UX 우선, Markdown/표 두 번째) 기준:

1. **Word Wrap 상태-실제 불일치 해소**: 메뉴가 거짓 상태를 보여주는 건 "Notepad-like 신뢰"에 직접 반함(`MainWindow.xaml:250,485`). 실제 토글 구현 또는 최소한 메뉴를 비활성+미체크로 정직하게 표시.
2. **캡처 제외 실제 매뉴얼 검증(Snipping/OBS/Recall)**: 이미 로드맵 "Next"에 있고, 프라이버시 기능이 사용자에게 이미 노출된 채 미검증인 것이 가장 큰 신뢰 리스크(`dev-progress.md:42`).
3. **"캡처 제한됨" 상태의 실질 의미를 사용자에게 명확히 설명**: 검은 사각형 폴백이라는 사실을 상태/툴팁 문구에 반영(`WindowsInterop/CaptureExclusion.cs:42-44`).
4. **설정 영속화 범위 확장(테마/글꼴/글꼴크기/줌)**: `dev-ux.md`가 V1 화면으로 명시한 항목인데 현재 캡처예외/최근파일 2개뿐 — 제품 목표(빠르고 익숙한 재실행 경험)에 직접 영향.
5. **번역 완성도 정리**: 11개 언어가 15%만 번역된 상태로 "다국어 지원"이라고 로드맵에 Done 처리된 것은 과장. 지원 언어 축소(예: en/ko만 완전 지원으로 명시) 또는 나머지 84개 키 채우기 중 하나를 결정.
6. **Markdown 미리보기-편집 도우미 정합**: 기울임/취소선/링크 렌더 추가(최소한 굵게처럼 정규식 1~2개 추가) — 사용자가 버튼을 눌러 만든 문법이 미리보기에 그대로 원문으로 남는 건 "표를 편집기처럼 보여준다"는 제품 목표에 어긋남(`MarkdownPreviewDocumentFactory.cs`).
7. **툴바 아이콘 버튼 접근성 이름 추가**: `AutomationProperties.Name` 부재는 적은 작업으로 해소 가능한 접근성 결함(`MainWindow.xaml:293-373`).
8. **인코딩 처리 재검토**: 상태바가 항상 "UTF-8"만 표시하는 게 사실과 다를 수 있음(ANSI 파일을 열어도 UTF-8이라 표시) — Notepad 기본기 격차 중 사용자가 가장 먼저 체감할 항목.
9. **하드코딩된 영어 문자열(Missing image/Remote image) 로컬라이즈**: 리소스 시스템이 있는데 우회한 사례 — 작은 수정으로 일관성 회복.
10. **하위 우선순위**: Ctrl+H, Ctrl+마우스휠 줌, Ctrl+W/Ctrl+Tab 탭 단축키 — Notepad 기본기 격차지만 위 1~9 대비 리스크·사용자 체감이 낮음.
